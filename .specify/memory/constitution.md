# Principios del proyecto

1. Una historia debe tener criterios verificables antes de cambiar el código.
2. Las entidades contienen reglas del negocio. TLista conserva operaciones de lista.
3. Se declaran campos privados, constructor vacío, constructor con parámetros, propiedades explícitas y métodos en ese orden.
4. Toda condición, ciclo y evento usa llaves y líneas separadas.
5. Una función requiere pruebas de su resultado válido y de sus rechazos relevantes.
6. No se integra código que no compile o falle las pruebas.
7. La IA propone y el estudiante revisa, comprende y valida.
8. Las evidencias deben distinguir trabajo ejecutado de pasos pendientes.

Estas especificaciones se redactaron siguiendo SDD. No se afirma que esta carpeta haya sido generada por el CLI de Spec Kit. La documentación explica cómo inicializar la herramienta oficial en una rama aparte si el grupo desea ejecutarla con Copilot.
